## Not automated, and known limits

- The native open dialog and Finder drag-and-drop cannot be driven by a script. The test stubs the dialog's file list (`STUDIO_E2E_PICK_FILE`, development builds only) and calls the same import path for drops; `webUtils.getPathForFile` is not exercised.
- Fixtures are synthetic (ffmpeg test patterns, short). The exit bar of 10 real phone clips in under 2 minutes, and the 8GB memory budget, still need a run on the 8GB Mac with real footage.
- Every video gets a proxy (no "already small enough" shortcut), so constant frame rate is guaranteed.
- Dropped paths come from the renderer; main re-validates them (media extension on the real file, regular file, not inside app data) but cannot prove they came from a real drop.

## Independent review (Opus subagent) and what was done

13 findings. Fixed: queue stall when the worker window is destroyed or crashes (finish on close, single crash listener, start timeout, 120s silence watchdog); import temp files deleted by job cleanup (jobs now sweep `cache/*.part` only, stale import temps are swept on open); cancelled jobs still writing (writes rejected, deletes and project removal wait for the job to stop); assets deleted after a failed save; cancelled job blocking a reopen's re-queue; "missing" flags wiped by partial checks; project folder recreated by a late write (non-recursive mkdir); image over 50MP and absurd durations (header check, 12h cap); relink to a different media type (rejected); listener leak; double-open of a cache file; 8GB file cap and free-space check on copy. Covered by unit tests (stale vs live temp files) and an e2e check (import during a running job).
Not fixed: (10) the renderer can still ask main to copy any readable media file by path (needed for Finder drops; a one-shot token from a real drop event would close it, planned for M7 hardening); (13) files copied just before a window close inside the 800ms autosave debounce stay in `assets/` as orphans until "Remove unused" is extended to find them.
