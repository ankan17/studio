## Not automated, and known limits

- The native open dialog and Finder drag-and-drop cannot be driven by a script. The test stubs the dialog's file list (`STUDIO_E2E_PICK_FILE`, development builds only) and calls the same import path for drops; `webUtils.getPathForFile` is not exercised.
- Fixtures are synthetic (ffmpeg test patterns, short). The exit bar of 10 real phone clips in under 2 minutes, and the 8GB memory budget, still need a run on the 8GB Mac with real footage.
- Every video gets a proxy (no "already small enough" shortcut), so constant frame rate is guaranteed.
- Dropped paths come from the renderer; main re-validates them (media extension on the real file, regular file, not inside app data) but cannot prove they came from a real drop.
